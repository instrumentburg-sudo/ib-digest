Наблюдаемость Hermes Agent через Grafana

Что случилось на Hacker News показали подключаемый модуль grafana-agento11y-hermes. Он пишет вызовы моделей и инструментов как трассировки OpenTelemetry; свежая версия 0.9.0 связывает вызов инструмента с породившим его ответом модели. На момент сбора обсуждение набрало 27 баллов. Важная оговорка: по умолчанию наружу уходит полный текст; безопасный режим — AGENTO11Y_CONTENT_CAPTURE_MODE=metadata_only.

Живой пример репозиторий и инструкция — https://github.com/alexander-akhmetov/grafana-agento11y-hermes

👉 Как применить: протестировать на отдельном профиле Hermes в режиме только метаданных. Это даст реальные цифры по длительности, ошибкам инструментов и расходу моделей для ежедневных агентов без утечки переписки.

Needle 2: локальный вызов инструментов в 14 МБ

Что случилось Needle 2 попал в GitHub Trending и получил 443 звезды за сутки. Авторы заявляют 45 млн параметров, файл 14 МБ, около 28 МБ оперативной памяти, структурированный JSON и порог уверенности для передачи сомнительных случаев большой модели.

Живой пример код, установка и пример функции-инструмента — https://github.com/cactus-compute/needle

👉 Как применить: не тащить в основного ассистента. Проверить как дешёвый локальный классификатор для маршрутизации писем, заявок и простого извлечения полей; решения и ответы клиентам оставить большим моделям.

Unsloth снова в дневном тренде GitHub

Что случилось репозиторий получил 572 звезды за сутки. Это не новый релиз: свежий интерес пришёл к настольному приложению, которое запускает локальные модели, отдаёт совместимый с OpenAI API и подключает Claude Code, Codex и MCP. Проект насчитывает 72 792 звезды и обновлялся сегодня.

Живой пример репозиторий и варианты установки — https://github.com/unslothai/unsloth

👉 Как применить: наблюдать, но не заменять рабочий Ollama. Практический тест оправдан только для одного сценария: единый экран для локальных моделей и MCP без ручной сборки окружения.

«Пишет человек, проверяет агент» вместо слепого вайб-кодинга

Что случилось на Hacker News обсуждают рабочую схему из двух этапов — человек пишет код, AI проверяет его как рецензент. Обсуждение набрало 81 балл и 48 комментариев на момент сбора. Главный довод: быстро сгенерированный код невозможно внимательно проверять строка за строкой, поэтому роли лучше перевернуть.

Живой пример статья с разбором процесса — https://peterbloem.nl/blog/craft-coding

👉 Как применить: для критичных частей калькулятора, оплат и синхронизации заказов закрепить режим «человек или один агент пишет — другой агент ищет ошибки», с тестами до публикации. Для типовой вёрстки и одноразовых сценариев нынешний быстрый режим можно оставить.
