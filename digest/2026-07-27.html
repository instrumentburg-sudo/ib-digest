Open Code Review 1.7.17: отдельный инструмент для разбора кода

Что случилось Alibaba выпустила версию 1.7.17 с поддержкой OpenCode, проверками корректности макросов Rust и файлов Julia. Репозиторий набрал 832 звезды за сутки и 14 101 звезду всего. Авторы строят проверку в два слоя: жёсткий отбор файлов и правил плюс агент для поиска контекста. По их тесту на 200 реальных запросах на слияние такой подход тратит примерно в девять раз меньше токенов, чем универсальный агент, но пропускает больше дефектов.

Живой пример https://github.com/alibaba/open-code-review/releases/tag/v1.7.17

👉 Как применить: прогнать инструмент на одном нашем запросе на слияние и сравнить найденные дефекты, ложные срабатывания и расход токенов с текущим разбором через Claude Code. Пока не внедрять в обязательную проверку.

Buzz добавил прямой запуск Hermes Agent и OpenClaw

Что случилось в Buzz появился единый слой ACP для разных агентов. В готовые варианты включили Hermes Agent, OpenClaw, Claude Code, Codex, OpenCode и Kimi; свои варианты можно задавать через JSON. Изменение прошло 1 701 тест Rust и 3 605 тестов настольного приложения. Сам Buzz сегодня набрал 1 710 звёзд на GitHub Trending.

Живой пример https://github.com/block/buzz/commit/95fdf978800982389b120c66ff5e766d785419c7

👉 Как применить: следить, а не переносить туда работу сейчас. Buzz интересен как единый журнал для людей и нескольких агентов, но наш штаб уже живёт в Telegram, GitHub и Hermes. Возвращаться к пробе стоит, когда параллельных агентов станет столько, что начнут теряться решения и история согласований.

👉 Как применить: WhatsApp не ставить. Взять его трёхслойную защиту как список проверки для наших Telegram-агентов: белый список, роли, отдельный перехватчик действий с запретом по умолчанию.

Маркетинговая память Claude Code в Git, а не в длинном промпте

Что случилось автор из r/ClaudeAI показал рабочую систему, где Claude Code ведёт маркетинг проекта. Позиционирование, площадки, контакты и очередь публикаций лежат в типизированных Markdown-файлах внутри Git; схема проверяет структуру, а история изменений не даёт памяти расползаться. Это живой пример того, что инструкции и рабочее состояние лучше хранить раздельно.

Живой пример https://www.reddit.com/r/ClaudeAI/comments/1v7nrzg/i_run_my_projects_marketing_with_claude_code_the/

👉 Как применить: собрать такой же реестр для ИнструментБург: кампания, площадка, дата публикации, результат, повторный контакт и причина решения. Claude Code должен читать факты из файлов, а не восстанавливать их по переписке.

AI ускоряет запуск, но плодит недоделанные проекты

Что случилось обсуждение на Hacker News набрало 186 голосов и 54 комментария к моменту сбора. Автор держал больше 100 идей статей и 50 проектов, запускал Claude короткими пятиминутными подходами и в итоге получил перегруз вместо освобождённого времени. В комментариях повторяется тот же рабочий перекос: быстрый прототип теперь легко выдать за понимание задачи, а сложность и сопровождение всплывают позже.

Живой пример https://news.ycombinator.com/item?id=49057877

👉 Как применить: держать правило «одна главная задача и две малые». Новую автоматизацию не начинать, пока предыдущая не даёт проверяемый результат и не назначен человек, который будет её сопровождать.
